# Миграция на нового бота

Пошаговый чеклист для переезда на новый Telegram-аккаунт бота.

---

## 1. Создай нового бота у @BotFather

1. `/newbot` → задай имя и username
2. Скопируй токен
3. Включи **Business Mode**: `/mybots` → выбери бота → Bot Settings → Business Mode → Enable
4. Если нужен inline-режим: `/setinline` → задай подсказку

---

## 2. Обнови секреты и переменные окружения

| Переменная | Что поменять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен нового бота от @BotFather |
| `WEBHOOK_BASE_URL` | URL деплоя (если переезжаешь на новый хост) |
| `TELEGRAM_WEBHOOK_SECRET` | Сгенерируй новую строку: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `MINIAPP_ADMIN_USERNAME` | Telegram-username нового администратора (без @) |
| `SESSION_SECRET` | Можно оставить старый если БД переезжает целиком, иначе сгенерируй новый |
| `DATABASE_URL` | Только если переезжаешь на новую БД |

Все остальные переменные (GEMINI_API_KEY, RAILWAY_API_TOKEN и т.д.) бота не касаются — меняй только при необходимости.

---

## 3. Что переезжает само (ничего делать не нужно)

- Вся база данных: пользователи, монеты, питомцы, отношения, рефералы, статистика
  — всё привязано к Telegram user ID, а не к боту
- История чатов в БД (удалённые/отредактированные сообщения)

Подписки Stars — charge ID хранится в БД, но refund через старого бота после смены токена невозможен.

---

## 4. Что НЕ переезжает само

### Business-подключения пользователей

Все пользователи должны переподключить бота вручную:

  Настройки Telegram → Автоматизация чатов → удалить старого → добавить нового

Старые business_connection_id в БД станут невалидными. Новые придут по мере переподключения.

Опционально — очисти таблицу до запуска чтобы не было мёртвых записей:

```sql
DELETE FROM business_connections;
```

### Webhook

После смены токена старый webhook удаляется автоматически. Новый зарегистрируется сам при старте (если WEBHOOK_BASE_URL задан).

Проверить: https://api.telegram.org/bot<TOKEN>/getWebhookInfo

---

## 5. Порядок действий при деплое

```
1. Остановить текущий инстанс
2. Обновить переменные окружения (токен, секреты, admin username)
3. Запустить приложение
4. Убедиться что webhook зарегистрировался (логи: "Telegram webhook set to ...")
5. Написать боту /start — проверить что отвечает
6. Уведомить пользователей о смене бота
```

---

## 6. Уведомление пользователей

Используй /broadcast из старого бота (пока он ещё работает) чтобы разослать сообщение. Шаблон:

```
Бот переехал на новый аккаунт!

Чтобы продолжить работу:
1. Настройки → Автоматизация чатов
2. Удали старого бота
3. Добавь @NEW_BOT_USERNAME

Все твои данные (монеты, питомец, статистика) сохранены.
```

---

## 7. Финальная проверка

- [ ] /start отвечает корректно
- [ ] /help → «Как подключить» показывает правильный username нового бота
- [ ] Business-подключение работает (проверь на своём аккаунте)
- [ ] Мини-приложение открывается
- [ ] Админ-панель доступна под новым MINIAPP_ADMIN_USERNAME
- [ ] Скачивание видео/музыки работает
- [ ] Webhook Info: pending_update_count == 0
